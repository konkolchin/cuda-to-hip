## 0. Короткая рамка (как договорились)

Не выдуманный стартап и не сухой «заказчик PoC».

Сначала была AMD-машина: Ryzen 7 7700X + Radeon RX 7900 XTX (`Deck/Slide12.jpg`) — обычный потребительский ПК. Почему Milvus — самая популярная open-source векторная БД для RAG/ANN (~46k звёзд, слайд 2). Не потому что «аналогов не было». GPU-поиск Milvus на consumer Radeon не работал (CUDA/cuVS; hipVS 0.1.0 только Instinct — `Deck/Slide2.jpg`).

Порт сначала на этой AMD машине. Когда поиск заработал, нашли финансирование на покупку машины с NVIDIA чтобы сравнить и опубликовать (`Deck/Slide4–6.jpg` — графики с дашборда).

Один текст. Medium и блог AMD — одно тело. LinkedIn — сокращение. Цифры и графики — с деки / ночного дашборда, не со старых разовых прогонов harness, если они расходятся.

Уточнить до публикации: точная **модель Intel CPU** на машине с 4080 (на слайде 12: «16 logical CPUs, model not recorded»). Видеокарта NVIDIA — **RTX 4080 16 GB**, не «4080 XTX».

## 3. Сюжет (компромисс)

Не вымышленный стартап. Не «у нас сразу была пара NVIDIA». Порядок:

1. **Только AMD.** Ryzen 7 7700X, 64 ГБ, RX 7900 XTX 24 ГБ, Ubuntu 22.04.5, ROCm 7.0.2. Нужен был GPU vector search. Карта — Radeon. Штатный GPU Milvus — CUDA. hipVS 0.1.0 — Instinct. На consumer Radeon GPU-поиска не было.
2. **Порт на этой машине.** Tech-preview, Milvus v2.5.4, два GPU-индекса: `GPU_IVF_FLAT` и `GPU_IVF_PQ`.
3. **Потом 4080.** Чтобы сравнить и опубликовать. Ночной CI, те же запросы, обе карты.

Зачем vector search (честно): эмбеддинги на вход, ближайшие соседи на выход — RAG. Мы не утверждаем, что выпустили именной RAG-продукт. Если появится реальное имя внутренней задачи — вставим.

### 3.1 Почему Milvus

Вести с популярности (не со списка конкурентов).

> Выбор пал на Milvus потому, что это самая популярная open-source векторная БД для RAG / ANN (~46 тыс. звёзд на GitHub — слайд 2). Не потому, что «других не было»: FAISS — библиотека, pgvector — расширение Postgres, облака нам не подходили. Нужен был стек, который ставят в RAG, с GPU-индексами. У Milvus GPU-путь на NVIDIA; на consumer Radeon его не было.

Для фактчека: «самая популярная **open-source** векторная БД для RAG», не «самая популярная БД в мире» и не «вариантов не было».

### 1. Крючок (цель, не спецификация ПК)

Не начинать с Ryzen / 64 ГБ. Спринт: нужна RAG/векторная БД, хотели Milvus, GPU была consumer Radeon, GPU-индексы Milvus — только NVIDIA.

### 2. Задача

- GPU ANN в Milvus на **Ryzen + RX 7900 XTX** (`Deck/Slide12.jpg`).
- Почему не только CPU: дырка — GPU-поиск на карте, которую уже купили (`Deck/Slide2.jpg`).
- NVIDIA **RTX 4080 16 GB** — **позже**, ближе к графикам (замечание Александра), не в первом экране.
- Конфиг = слайд 12.



### 3. Стек

```
pymilvus / VectorDBBench
        → сервер Milvus
            → Knowhere (CPU + GPU индексы)
                → GPU_IVF_FLAT / GPU_IVF_PQ / GPU_CAGRA
                    → NVIDIA: RAFT / cuVS
                    → AMD:    hipRAFT / hipVS
```

Python-клиент не вызывает cuVS сам. Порт — Knowhere + GPU-библиотека, **сборка из исходников**.

### 4. Слои (как делали)

Не «переписали за выходные».


| Слой | Что                 | Проход                                                     |
| ---- | ------------------- | ---------------------------------------------------------- |

### 5. Два способа работы с агентами (не один слоган)

**Линия 1 — Костя:** помощник в IDE (Cursor / Grok). Человек правит код, гоняет гейты, решает, какая цифра уходит наружу. Слои, packer, графики ниже — эта линия.

**Линия 2 — Максим:** замкнутый агентный пайплайн (схема v3). Руками в C++ не лез. Задача: адаптировать hipVS/hipRAFT, собрать Knowhere, тесты, ревью запуска на gfx1100. Не переписывать кернелы под RDNA3. Публичного GitHub нет; дашборд надо перезапускать. Черновик главы — в `article_milvus_hip_v1.md`, ждём правок Максима.

Не выдумывать, что «агент сам спроектировал порт».

### 6. Что портировано

Публичная заявка как на слайде 3: **два** GPU-индекса.


| Индекс         | В статье                     | В лаборатории                             |
| -------------- | ---------------------------- | ----------------------------------------- |
| `GPU_IVF_FLAT` | Готово, дашборд GIST-1M      | без сжатия; Radeon впереди на всех nprobe |
| `GPU_IVF_PQ`   | Готово, дашборд GIST-1M      | сжатие; сначала AMD, потом NVIDIA         |
| `GPU_CAGRA`    | **Следующий шаг** (слайд 10) | unfiltered в лабе есть; не как «сделано»  |
| CPU-индексы    | Уже работали                 | не сюжет                                  |


Инженерия коротко: IVF packer / warp32; `blockDim=512` на hipVS PQ (микробенч библиотеки, не QPS Milvus).

### 7. Как мерили (дашборд, дека)

Дашборд есть (слайд 7). Слайды 5–6 — графики. В публикацию — **только сам график**, без рамки слайда DXC (замечание Александра).

Протокол (слайд 4):

- те же данные, запросы, линия сборки на обеих картах
- ночной CI: один sweep **1000 раз** на карту
- медиана QPS; только прогоны с верными соседями (exact-kNN)
- усы ±1σ
- датасет **GIST-1M** (960-d, влезает в VRAM обеих: 24 vs 16 ГБ)
- пара: RX 7900 XTX vs RTX 4080

Если старый harness расходится с декой — **дека**.

### 8. Итог: задачу закрыли?

Да. GPU-поиск на consumer Radeon. Два IVF-индекса. Соседи проходят тот же гейт, что на 4080.

QPS (дашборд, GIST-1M, медиана 1000 прогонов):


| Индекс         | Картина                             | Цифра                                              |
| -------------- | ----------------------------------- | -------------------------------------------------- |
| `GPU_IVF_FLAT` | Radeon впереди на **каждом** nprobe | **+26%** AMD при nprobe 8                          |
| `GPU_IVF_PQ`   | AMD до nprobe 32, дальше NVIDIA     | **+36%** при 8; **−22%** при 128 (`1.36× → 0.78×`) |


Слайд 13: без сжатия Radeon уже быстрее без тюнинга под Radeon. Сжатие на большом nprobe — цель тюнинга (~22%).
